## 需求背景

校园内存在跨校区、宿舍区、教学楼、科技园、附属医院等通勤需求。传统校车预约依赖人工统计，存在预约数据不透明、司机任务通知滞后、调度缺少数据支撑、后台无法实时掌握车辆运行情况等问题。因此需要设计一个校车管理系统，将乘客预约、司机派车、车辆司机管理、实时位置和运营分析统一到一个课程原型系统中。

当前项目定位为《软件开发环境与工具》课程大作业原型。系统使用 Flutter/Dart 实现三端功能闭环，使用 Mock Repository 提供演示数据；支付、GPS、地图和后端能力均为 Mock 或可切换骨架，不表示真实支付扣款、真实 GPS 采集或正式后端上线。

## 总体业务流程

1. 普通用户登录用户端，查看可预约车次，选择车次和座位生成预约订单。
2. 普通用户可支付车费，系统生成 Mock 支付流水和通知。
3. 普通用户可取消待发车预约，系统按发车时间扣减信用分。
4. 后台管理员查看预约需求汇总，根据人数和车辆情况进行人工调度或 AI 辅助调度。
5. 调度确认后，车辆状态变为运行中，并进入后台 Mock 实时位置监控。
6. 司机登录司机端，查看今日任务、乘客名单和上车点，点击开始任务后共享 Mock 实时位置。
7. 后台管理员在 Mock 地图中查看车辆、司机、车次、速度、坐标、预约客户距离和预计到达时间。
8. 系统按日、周、月统计司机任务和后台运营数据。

| 输入 | 手机号、密码、当前入口模式 |

## 业务规则

| 编号 | 规则 | 自动化覆盖 |
| --- | --- | --- |
| RUL-01 | 用户只能登录与当前入口一致的角色 | `TC-18` |
| RUL-02 | 只有待发车且未过发车时间的车次可预约 | `TC-02`、手工测试 |
| RUL-03 | 同一用户不能重复预约同一车次 | `TC-19` |
| RUL-04 | 只有待发车预约可以取消 | `TC-20` |
| RUL-05 | 距发车时间小于等于 2 小时取消扣 5 分，大于 2 小时扣 2 分 | `TC-03` |
| RUL-06 | 只有待支付且待发车预约可以支付 | `TC-04`、手工测试 |
| RUL-07 | 运行中车辆不可删除 | `TC-21` |
| RUL-08 | 在途司机不可删除 | 手工测试 |
| RUL-09 | 车辆绑定保持一车一司机 | `TC-22` |
| RUL-10 | 调度车辆必须为空闲状态，且座位数不小于预约人数 | `TC-23` |
| RUL-11 | AI 调度只选择空闲且已有绑定司机的车辆；无候选车辆时返回失败提示 | `TC-24` |
