## 需求背景

校园内存在跨校区、宿舍区、教学楼、科技园等通勤需求。传统校车预约依赖人工统计，存在车次需求不透明、司机任务通知滞后、调度缺少数据支撑、后台无法实时掌握车辆运行情况等问题。因此需要设计一个校车管理系统，将乘客预约、司机派车、车辆司机管理、实时位置和运营分析统一到一个系统中。

## 用户角色

| 角色 | 说明 | 主要目标 |
| --- | --- | --- |
| 普通用户 | 学生或教职工乘客 | 查询车次、预约座位、支付车费、取消预约、查看信用等级 |
| 司机 | 校车驾驶员 | 查看派车任务、查看乘客和上车点、发车后共享位置、查看任务统计 |
| 后台管理员 | 校车运营管理人员 | 管理车辆司机、调度车次、监控车辆、分析运营数据 |

## 总体业务流程

1. 普通用户登录用户端，查看可预约车次，选择车次和座位生成预约订单。
2. 普通用户可支付车费，系统生成支付流水和通知。
3. 普通用户可取消待发车预约，系统按发车时间扣减信用分。
4. 后台管理员查看预约需求汇总，根据人数和车辆情况进行人工调度或 AI 辅助调度。
5. 调度确认后，车辆状态变为运行中，并进入后台实时位置监控。
6. 司机登录司机端，查看今日任务、乘客名单和上车点，点击开始任务后共享实时位置。
7. 后台管理员在地图中查看车辆、司机、车次、速度、坐标、预约客户距离和预计到达时间。
8. 系统按日、周、月统计司机任务和后台运营数据。

## 功能需求

### FR-01 登录和角色入口

| 项目 | 内容 |
| --- | --- |
| 说明 | 系统支持普通用户、司机、后台管理员三种角色登录 |
| 输入 | 手机号、密码、当前入口模式 |
| 处理 | 校验 Mock 账号、密码和角色是否匹配当前入口 |
| 输出 | 登录成功后进入对应工作台，失败时提示原因 |
| 源码 | `lib/features/auth/data/mock_auth_repository.dart`、`lib/core/router/app_router.dart` |

### FR-02 普通用户预约车次

| 项目 | 内容 |
| --- | --- |
| 说明 | 普通用户可查看可预约车次并选择座位预约 |
| 输入 | 车次 ID、座位号、用户 ID |
| 处理 | 判断车次是否待发车、是否有余座、是否重复预约、座位是否可选 |
| 输出 | 生成预约订单，预约状态为待发车，支付状态为待支付 |
| 源码 | `PassengerBookingController.createBooking` |

### FR-03 普通用户查看和筛选预约

| 项目 | 内容 |
| --- | --- |
| 说明 | 普通用户可查看全部、待发车、已完成、已取消预约 |
| 输入 | 用户 ID、预约状态筛选条件 |
| 处理 | 按用户和状态过滤预约列表 |
| 输出 | 预约列表，包含车次、座位、费用、支付状态、信用扣分信息 |
| 源码 | `PassengerBookingState.bookingsForUser`、`_BookingFilterBar` |

### FR-04 普通用户取消预约和信用扣分

| 项目 | 内容 |
| --- | --- |
| 说明 | 普通用户可取消待发车预约，系统按规则扣减信用分 |
| 输入 | 预约 ID |
| 处理 | 仅允许取消待发车预约；距发车小于等于 2 小时扣 5 分，大于 2 小时扣 2 分 |
| 输出 | 预约状态变为已取消，记录扣分，支付订单如已支付则标记退款 |
| 源码 | `PassengerBookingController.cancelBooking`、`cancellationPenaltyForTrip` |

### FR-05 普通用户支付车费

| 项目 | 内容 |
| --- | --- |
| 说明 | 普通用户可对待支付预约进行 Mock 微信支付或支付宝支付 |
| 输入 | 预约 ID、支付方式 |
| 处理 | 生成支付流水，先置为支付中，延迟 500ms 后置为已支付 |
| 输出 | 预约支付状态变为已支付，通知中心生成支付成功通知 |
| 源码 | `PassengerBookingController.payBooking`、`PaymentModel` |

### FR-06 普通用户信用等级和通知

| 项目 | 内容 |
| --- | --- |
| 说明 | 普通用户可查看信用分、等级、扣分记录和 Mock 推送通知 |
| 输入 | 用户信用分、预约扣分记录、通知列表 |
| 处理 | 按信用分划分优秀、良好、一般、受限 |
| 输出 | 信用等级面板、扣分记录、通知中心 |
| 源码 | `_CreditPanel`、`notification_provider.dart` |

### FR-07 司机查看派车任务

| 项目 | 内容 |
| --- | --- |
| 说明 | 司机可查看今日派车任务列表和任务详情 |
| 输入 | 司机 ID |
| 处理 | 加载 Mock 派车任务 |
| 输出 | 车次号、路线、发车时间、车辆、距离、乘客名单和上车点 |
| 源码 | `driver_home_page.dart`、`mock_driver_repository.dart` |

### FR-08 司机任务统计

| 项目 | 内容 |
| --- | --- |
| 说明 | 司机可按日、周、月查看完成车次、服务人次、行驶里程和准点率 |
| 输入 | 统计周期 |
| 处理 | 从 Mock 统计列表中选择对应周期 |
| 输出 | 统计看板和准点率进度条 |
| 源码 | `DriverStats`、`DriverTaskController.selectStatsPeriod` |

### FR-09 司机实时位置共享

| 项目 | 内容 |
| --- | --- |
| 说明 | 司机发车后共享车辆位置，到站后停止共享 |
| 输入 | 任务 ID |
| 处理 | 任务状态变为运行中，每 5 秒模拟生成经纬度和速度 |
| 输出 | 最新位置、上报次数、共享状态 |
| 源码 | `DriverTaskController.startTask`、`LocationUpdate` |

### FR-10 后台车辆管理

| 项目 | 内容 |
| --- | --- |
| 说明 | 管理员可新增、编辑和删除车辆 |
| 输入 | 车牌号、车型、座位数、车辆状态 |
| 处理 | 校验必填、车牌唯一、运行中车辆不可删除 |
| 输出 | 车辆列表更新 |
| 源码 | `AdminController.addVehicle`、`updateVehicle`、`deleteVehicle` |

### FR-11 后台司机管理

| 项目 | 内容 |
| --- | --- |
| 说明 | 管理员可新增、编辑和删除司机，并绑定车辆 |
| 输入 | 姓名、手机号、驾照号、绑定车辆 |
| 处理 | 校验必填、手机号唯一、一车一司机、在途司机不可删除 |
| 输出 | 司机列表更新 |
| 源码 | `AdminController.addDriver`、`updateDriver`、`deleteDriver` |

### FR-12 后台人工和 AI 辅助调度

| 项目 | 内容 |
| --- | --- |
| 说明 | 管理员可根据预约需求生成人工调度方案或 AI 推荐方案 |
| 输入 | 待调度需求、空闲车辆、司机绑定关系 |
| 处理 | 人工选择车辆司机；AI 按需求人数降序匹配空闲且已绑定司机的车辆 |
| 输出 | 调度方案，确认后需求已调度，车辆运行中，并生成实时位置记录 |
| 源码 | `generateAiDispatchPlans`、`createManualDispatchPlan`、`confirmDispatchPlan` |

### FR-13 后台实时位置监控和客户 ETA

| 项目 | 内容 |
| --- | --- |
| 说明 | 管理员可查看运行中车辆位置、司机信息、速度、坐标、预约客户距离和预计到达时间 |
| 输入 | 车辆位置、预约客户 Mock ETA 数据 |
| 处理 | 在 Mock 地图绘制车辆标记，点击标记显示详情，位置每 5 秒模拟刷新 |
| 输出 | 地图标记、车辆详情、预约客户 ETA 列表 |
| 源码 | `_TrackingPanel`、`_VehicleTrackingDetail`、`_PassengerEtaPanel` |

### FR-14 后台历史数据分析

| 项目 | 内容 |
| --- | --- |
| 说明 | 管理员可按日、周、月查看运营数据 |
| 输入 | 统计周期 |
| 处理 | 加载对应周期统计快照 |
| 输出 | 出行人次、收入、车辆利用率、趋势图、路线热度排行 |
| 源码 | `_AnalyticsPanel`、`AdminAnalyticsSnapshot` |

## 非功能需求

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-01 | 易用性 | 三端工作台采用卡片式布局，核心操作按钮明确 |
| NFR-02 | 可维护性 | 按 `core`、`features`、`shared` 分层组织代码，业务逻辑放在 Provider 中 |
| NFR-03 | 可测试性 | 关键流程提供 Widget 自动化测试 |
| NFR-04 | 可扩展性 | Mock Repository 可替换为 REST API、WebSocket、真实支付和地图服务 |
| NFR-05 | 响应式 | 页面使用 `LayoutBuilder` 和 `SingleChildScrollView` 适配窄屏和宽屏 |
| NFR-06 | 数据安全 | 当前为课程原型，不保存真实密码和支付信息；正式版本应增加加密存储和权限控制 |

## 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 用户只能登录与当前入口一致的角色 |
| BR-02 | 只有待发车且未过发车时间的车次可预约 |
| BR-03 | 同一用户不能重复预约同一车次 |
| BR-04 | 只有待发车预约可以取消 |
| BR-05 | 距发车时间小于等于 2 小时取消扣 5 分，大于 2 小时扣 2 分 |
| BR-06 | 只有待支付且待发车预约可以支付 |
| BR-07 | 运行中车辆不可删除 |
| BR-08 | 在途司机不可删除 |
| BR-09 | 车辆绑定保持一车一司机 |
| BR-10 | 调度车辆必须为空闲状态，且座位数不小于预约人数 |
| BR-11 | AI 调度只选择空闲且已有绑定司机的车辆 |
